01 / MEETING THE BRIEF

Meeting the brief

My project is a Premier League Statistics Tracker covering five seasons, from 2021–22 to 2025–26. It brings match results, team standings and player statistics together in one website. Users can choose a season and move between different sections instead of searching through separate statistics pages.

The application was built using Python and Streamlit. Pandas is used to read and filter the CSV datasets. The project contains three main data files: match information, player statistics and calculated league tables. An SQLite database is also included in the project, although the current website reads the CSV files directly and does not query the database.

The website has six main sections: Home, Players, Matches, League Table, Rankings and Analytics. Users can select a season, choose a player and view information in tables or charts. The intended users are football fans who want to explore historical Premier League data in a straightforward way.

02 / INVESTIGATION

Understanding the problem

The Premier League produces a large amount of information every season, including match results, team performance, league standings and player statistics. Football fans may want to compare clubs, check a player's contribution or see how goals and points are distributed. This information can be spread across different websites, so I wanted to bring it together in one place.

The intended users need to select a season, find a player or team, view match results and compare performances. This meant the website needed clear navigation, readable tables, useful column headings and charts that make comparisons easier to understand.

I considered how to store and process the information. CSV files are straightforward to read and process with Pandas. A relational database can organise related records into separate tables. My project includes an SQLite database, but the current version of the website reads the CSV files directly.

My aim was to make historical football statistics easier to access. I judged the idea by whether a user could find the information they needed and understand what the tables and charts were showing.

03 / PLAN

Planning the system

My hypothesis was that an interactive website would make Premier League statistics easier to access and compare. I planned six sections: Home, Players, Matches, League Table, Rankings and Analytics.

I chose Python and Streamlit to build the website. Pandas would read and filter the datasets, while Streamlit would create the pages, selection boxes, tables and charts. I planned to prepare the data first, build each page, add the season and player selections, and then test the information shown by the application.

I also planned to keep the layout consistent. A sidebar is used for navigation and season selection, so users do not have to learn a different layout for each page.

04 / DESIGN

Designing the system

The system takes information from the CSV datasets, processes and filters it with Pandas, and displays the results through Streamlit. The SQLite database is included as part of the project, but it is not currently queried by the website.

The Home page gives an overview of the selected season. Players focuses on an individual player, Matches lists fixtures and scores, League Table shows team standings, Rankings orders player statistics, and Analytics uses charts to compare teams and scoring.

The final colour scheme uses a white background, deep navy headings and navigation, blue highlights and pale-blue panels. I chose this brighter design to make the information easier to read. The same colours are used in the portfolio so that it matches the application.

05 / IMPLEMENTATION

Building the application

The main program is called premier_league_tracker.py. It uses Streamlit to build the website and Pandas to read the match, player and league-table CSV files. The selected season is used to filter the datasets before the relevant page is displayed.

The Home page shows an overview of the selected season, including match and goal statistics. The Players page lets the user select a player and view details such as their club, position, goals, assists, appearances and other statistics. Matches displays fixtures and results. League Table shows the final standings, Rankings displays lists such as top scorers and assist leaders, and Analytics displays charts for team comparisons.

How I developed my code

As I developed the project, I had to learn how to use Python libraries and Streamlit features that I had not used before. I used the official documentation for Python, Pandas and Streamlit, as well as W3Schools tutorials, to learn about different programming concepts. I read explanations and examples, tried ideas in my own project and changed them to suit the datasets I was using.

I also used ChatGPT as a learning resource when I was unsure how to approach a coding problem or wanted an explanation of a Python or Streamlit feature. I used the explanations to help me understand the steps involved, then wrote and adapted the code myself. I did not copy and paste code directly from ChatGPT into my project. I tested my own code and made changes when the result was not what I expected.

For example, I needed to learn how to load CSV files and select records for one season. I used Pandas' read_csv() function to load the data, then used filtering to create a smaller dataset for the season selected by the user. I checked the results by comparing the records shown on the website with the source data.

I also had to work out how to display tables and make them easier to understand. I used Streamlit's dataframe display and column configuration options. Some of the original column names were joined together, so I created a function that changes technical names into clearer labels without changing the actual column names used by the program.

When errors occurred, I read the error message, checked the relevant part of the code and tried to identify what was causing the problem. One example was making sure that the program could find the data folder when it was started. I used the location of the Python file to build the data-file paths, rather than relying on the folder from which the program happened to be launched.

This process helped me understand how the different parts of the application work together. I learned by reading documentation, testing small changes and checking whether the result was what I expected.

06 / TESTING

Testing the system

I tested the data and the main parts of the website to check that the information was being displayed correctly. The data checks covered all five seasons. Each full Premier League season should contain 380 matches and 20 teams. I also recalculated the league tables from the match results and checked the average-goals calculation used on the dashboard.

I checked player records as well. Some statistics are missing from the original dataset, so I checked that these missing values did not stop the player page from loading. The navigation links in the portfolio were also checked to make sure that they pointed to the correct sections.

07 / EVALUATION

Evaluating the project

My original aim was to make Premier League statistics easier to access and compare. The finished application brings season summaries, player statistics, match results, league standings, rankings and team analytics together in one place. This supports the aim of the project.

A strength of the website is that information is separated into clear sections. The Home page gives a quick overview, while Players and Matches provide more detail. League Table, Rankings and Analytics give users different ways to compare teams and players. The season selector also allows users to explore several years without opening a separate application for each season.

There are still areas that could be improved. The alignment of numbers in tables does not yet fully match the column headings, as identified during external user testing. Some player statistics are missing from the source data, and the application currently uses historical rather than live information. The SQLite database is included in the project but is not yet connected to the website.

If I continued the project, I would resolve the table alignment issue, improve the display of missing values, add a way to compare two players or teams, and connect the website directly to the SQLite database. I would also carry out further user testing after making these changes.

Overall, the project provides an interactive way to explore five seasons of Premier League data. Developing it helped me improve my understanding of Python, Pandas, Streamlit, data handling and testing a software application.
